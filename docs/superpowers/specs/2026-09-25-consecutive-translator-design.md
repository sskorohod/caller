# Последовательный переводчик aidispatch V2 в LingoLine

Дата: 2026-09-25
Статус: согласован (вариант A — точный перенос + Silero). Заменяет голосовые движки из
`2026-09-16-openai-realtime-translation-design.md` (realtime) и Grok Voice Agent.

Источник: `~/aidispatch`, `agent/consecutive/*` на коммите `9e4b1eb` (выпуск 2.29.0 — правки
по первым живым звонкам V2: «поздняя» короткая реплика, слово чужим алфавитом в начале речи,
пробелы между кусками перевода, keep-alive и прогрев соединений с OpenAI). Там это «переводчик по
спеке V2», выбранный Славой по живым звонкам 24.09: V1 (`gpt-realtime-translate`) перевёл
«послезавтра» как «tomorrow morning» и переходил на «ты». Более поздние правки aidispatch — вне этой
работы, переносятся отдельно.

---

## 1. Цель

Перенести переводчик aidispatch в caller полностью и сделать его единственным голосовым движком:

- голосовые режимы (двусторонний и односторонний) на парах языков с разными алфавитами идут через
  новый `ConsecutiveTranslator`;
- `services/realtime-translator.ts` (gpt-realtime-2.1) и `services/conference-translator.ts`
  (Grok Voice Agent) удаляются;
- каскад Deepgram (`StealthTranslator`) остаётся для stealth (тихий текст), для пар с одним
  алфавитом и как аварийный откат.

Что это даёт по сравнению с синхронными движками: перевод звучит, когда человек **закончил мысль**
(пауза + судья по смыслу), а не поверх него; «угу» не обрывает перевод, «стоп» обрывает сразу;
продолжение мысли вливается в ту же реплику; эхо громкой связи отсекается, только если замер его
нашёл.

### Критерии приёмки

1. Входящий звонок на паре ru↔en переводится в обе стороны последовательно: перевод начинается
   после паузы, а не поверх говорящего.
2. Сцена прогона (§7.2) проходит: все реплики переведены целиком, монолог — одной репликой,
   «угу» поверх перевода его не обрывает, «Stop.» обрывает; задержка «конец речи → первый звук»
   p50 ≤ 1,5 с (в aidispatch на той же сцене 1,27 с; сцена идёт без PSTN, так что цифры
   сравнимы напрямую).
3. Страница `/translate/<token>` работает без правок: события Socket.IO того же формата.
4. Биллинг, запись, Telegram, share-token, переключение в stealth посреди звонка работают.
5. `VOICE_ENGINE=pipeline` возвращает голос на каскад без пересборки.
6. `npx tsc --noEmit` чист, `npm test` (новый) зелёный.

## 2. Выбор движка (`routes/webhooks/media-stream.ts`, `buildTranslator`)

```
stealth                                        → StealthTranslator(speak=false)   // без изменений
VOICE_ENGINE=pipeline или voice_engine=pipeline → StealthTranslator(speak=true)   // аварийный откат
пара языков с одним алфавитом                    → StealthTranslator(speak=true)
иначе                                          → ConsecutiveTranslator
```

- `VOICE_ENGINE` по умолчанию `consecutive` (docker-compose и код). Значения `realtime`/`grok`
  и поле `translator_defaults.voice_engine` со значениями `realtime`/`grok` больше ничего не
  значат — идут по умолчанию. `voice_engine=pipeline` у воркспейса по-прежнему уводит его на каскад.
- Если `ConsecutiveTranslator.start()` не поднялся (не загрузился детектор речи, не открылась
  сессия расшифровки), звонок не падает: `media-stream` строит каскад и работает на нём
  (как в aidispatch: «VAD did not load: staying on the old engine»).
- Смена языков на лету: пара с разными алфавитами меняется на месте; если новая пара с одним
  алфавитом (или наоборот) — движок меняется существующим механизмом `detach()` → carryover →
  `buildTranslator`. Для этого обработчик `translator:set-languages` в `socket-server.ts` зовёт
  новую функцию `setTranslatorLanguages(callId, my, target)` из `media-stream.ts` вместо прямого
  `ct.updateLanguages()`; она же обновляет `TranslatorCtx`.

## 3. Архитектура

Новый каталог `packages/backend/src/services/consecutive/`. Модули переносятся 1:1: имена,
состояния, команды, константы и комментарии-обоснования — из aidispatch. Отличия перечислены явно.

```
Twilio µ-law 8 кГц ─► decode ─► EchoMeter.line ─┐
                          └──► SileroVad (16 кГц) ├─ события речи ─► FloorManager ◄─ Judge (gpt-4.1-mini)
                                   │  кадры в темпе проверки                 │ команды
                                   ▼                                          ▼
                             TranscribeLeg (gpt-live-transcribe) ─ текст ─► floor.text   CascadeEngine
                                                                             (GPT-6 Luna → gpt-4o-mini-tts)
                                                                                  │ звук по репликам
                                    Twilio ◄─ TwilioOut ◄─ Playback ◄──────────────┘
```

| файл | источник | что делает |
|---|---|---|
| `policy.ts` | `policy.py` | слова, алфавит текста, язык по алфавиту, «угу», стоп-фразы, эхо-фильтр по тексту |
| `floor.ts` | `floor.py` | очерёдность: конец мысли, выпуск, очередь, перебивания, слияние, перезапуск, заготовка хвоста |
| `judge.ts` | `judge.py` | «мысль закончена?» и «что значит речь поверх перевода?» |
| `echo.ts` | `echo.py` | есть ли на линии эхо нашего голоса (корреляция огибающих) |
| `transcribe.ts` | `transcribe.py` | сессия расшифровки на весь звонок, переподключение |
| `engine.ts` | `engine_v2.py` | перевод текстом и озвучка заранее, по фразам, строго по порядку |
| `playback.ts` | `playback.py` | воспроизведение одной реплики за раз, пауза, перезапуск |
| `vad.ts` | новый | Silero VAD v5 с событиями, как у LiveKit |
| `twilio-out.ts` | новый | вывод в Twilio вместо трека LiveKit |
| `audio.ts` | новый | µ-law ⇄ PCM16, пересэмплинг 8→16, 8→24, 24→8 с фильтром |
| `settings.ts` | часть `config_store.py` | пороги из `platform_settings` с проверкой диапазонов |
| `translator.ts` | `call.py` | сборка звонка + интерфейс, который ждёт `media-stream` |

### 3.1 policy

Как в aidispatch, плюс таблица алфавитов для 13 языков caller:
`en es de fr pt it` → latin, `ru uk` → cyrillic, `zh` → han, `ja` → japanese (кана и иероглифы
вместе), `ko` → hangul, `ar` → arabic, `hi` → devanagari. Алфавит символа — через Unicode
Script (`\p{Script=…}`), буква/цифра — `\p{L}`/`\p{N}`. `isCrossScriptPair(a, b)` решает §2.
Пара `zh`+`ja` — одна группа (иероглифы общие), идёт на каскад.

### 3.2 floor

Чистая логика: события на входе (`vadStart`, `vadEnd(silenceS)`, `text(fragment)`, `judged`,
`intent`, `audio`, `translation`, `finished`, `greeting`, `setEcho`, `discard`, `tick`), команды
на выходе (`Opened Updated Judge Intent Release Play Stop Drop Commit Reopened Pause Restart
Prepare`), часы подставляются. Все константы — как в `floor.py`.

Одно добавление для одностороннего режима: `silentLangs` — языки, чьи реплики переводятся только
текстом. Такая реплика после выпуска не встаёт в очередь воспроизведения (её не ждут и она не
держит голову очереди); движок переводит её без озвучки, и по «готово» ядро закрывает её как
«done». По умолчанию множество пустое — поведение aidispatch.

### 3.3 judge

`gpt-4.1-mini` через Chat Completions, `response_format: json_schema strict`, `max_tokens: 40`,
`temperature: 0`, таймаут 2,5 с. Промпты — дословно из `judge.py`. Любой сбой → `null` (ядро
решает само). Модель судьи не настраивается.

### 3.4 echo

Как в `echo.py`, с одним изменением: `MAX_LAG` 50 → **100 кадров (2 с)**. У нас между «отдали
кадр» и «услышали эхо» лежат наша очередь до 400 мс и два плеча PSTN; у aidispatch задержка эха
была меньше. Кадры — 20 мс PCM16 8 кГц с обеих сторон.

### 3.5 transcribe

`wss://api.openai.com/v1/realtime?intent=transcription`, `session.update` с
`type: transcription`, `model: gpt-live-transcribe`, `languages: [a, b]`, `delay: low`; без
`turn_detection` и `noise_reduction` (обоснования — в `transcribe.py`). Commit — только по
команде ядра, не меньше 100 мс звука. Переподключение 0,5/1/2 с, три коротких сессии подряд —
сдаётся. Очередь отправки до 8 с. Цена $0.017/мин отправленного звука.

Формат входа: **`audio/pcmu` 8 кГц**, если модель его принимает (Twilio уже отдаёт µ-law —
пересэмплинг не добавит информации); иначе PCM16 24 кГц (пересэмплинг 8→24). Проверяется первым
шагом реализации на живом API; выбранный формат — константа модуля.

### 3.6 engine

`CascadeEngine` из `engine_v2.py`: законченные предложения живой расшифровки переводятся сразу
(`chat.completions` со `stream: true`, `reasoning_effort: none`, `max_completion_tokens: 64 +
2·len`), поток перевода режется `PhraseChunker` на фразы по 8–20 слов, фразы озвучиваются
`gpt-4o-mini-tts` (`response_format: pcm`, 24 кГц, `instructions` = `TTS_INSTRUCTIONS` из
aidispatch), до двух фраз одновременно, звук строго по порядку. Контекст — 3 прежних куска той же
реплики. Заготовка хвоста (`prepare`), перезапуск, переоткрытие, отмена — как в оригинале.

Отличия от оригинала:
- в системный промпт перевода добавляются тон (`TONE_INSTRUCTIONS[tone]`, пустой для «Как есть»)
  и `personal_context` (до 2000 знаков, помечен как данные, а не инструкции) — как в каскаде;
- `speaks(lang)`: для языков из `silentLangs` фразы не озвучиваются, только текст;
- голос и тон меняются на лету: новые фразы — новым голосом, новые переводы — с новым тоном;
- отмена — `AbortController` на реплику плюс общий таймаут 15 с на вызов.

Звук TTS пересэмплируется 24 → 8 кГц (КИХ-фильтр нижних частот ~3,4 кГц) сразу на входе в звонок:
дальше всё — PCM16 8 кГц.

### 3.7 playback и twilio-out

`Playback` — как в `playback.py` (одна реплика за раз, пауза с возвратом к началу фразы по паузе
0,24 с в нашем звуке, перезапуск, `undone`), кадры 20 мс PCM16 8 кГц (320 байт).

`TwilioOut` заменяет `rtc.AudioSource`:
- `write(frame)` кодирует в µ-law и шлёт `{event: 'media', streamSid, media: {payload}}`, но не
  дальше **400 мс** вперёд реального времени — ждёт, пока впереди станет меньше (это и есть темп
  воспроизведения, как `queue_size_ms=400` у LiveKit);
- `clear()` шлёт `{event: 'clear', streamSid}` и обнуляет опережение — перебивание глушит
  мгновенно;
- закрытый сокет — кадры молча выбрасываются.

### 3.8 vad

Silero VAD v5 (`assets/silero_vad_v5.onnx`) через `onnxruntime-web` (WASM, один поток). Семантика
повторяет `livekit.agents.inference.VAD`, которым пользуется aidispatch:
- модель на 16 кГц: вход 8 кГц удваивается, окно 512 отсчётов (32 мс) + 64 отсчёта контекста,
  состояние `[2,1,128]`;
- пороги как в aidispatch: включение 0,7, выключение 0,55 (включение − 0,15), речь от 0,2 с,
  тишина от 0,35 с;
- события: `inference` на каждое окно (`probability`, `rawAccumulatedSilence` — до учёта окна,
  как у LiveKit, `frame` — соответствующие 256 отсчётов 8 кГц), `start`, `end` (`silenceS`);
- одна сессия ONNX на звонок, окна обрабатываются строго по очереди.

Расшифровщик слышит линию кадрами, которые детектор уже проверил, а просьбу ядра закрыть сегмент
(`Commit`) исполняет в ближайшей тишине (≥ 0,35 с и вероятность < 0,5) или через 10 с — как
`_hear_checked` в `call.py`. Если детектор упал посреди звонка, линия снова идёт в расшифровщик
напрямую, а commit — сразу.

### 3.9 translator (сборка звонка)

`ConsecutiveTranslator` реализует тот же duck-typed интерфейс, что `StealthTranslator`:
`engine = 'voice'`, `workspaceId`, `start()`, `sendAudio(buf)`, `stop()`, `detach()`,
`updateLanguages`, `updateVoice`, `updateTone`, `updateMode`, `pause`, `resume`, `isPaused`.

- **Части подменяемы** (часы, выход, расшифровщик, детектор, судья, движок, клиент OpenAI) — для
  тестов и сцены прогона, как `parts` в `call.py`.
- **Соединения с OpenAI не остывают** (2.29.0): клиент OpenAI получает свой `https.Agent` с
  keep-alive на 5 минут — у SDK по умолчанию `agentkeepalive` закрывает простаивающий сокет через
  4 с, и каждая реплика после паузы открывала бы соединение заново (+0,1–0,2 с к переводу и к
  озвучке). На старте звонка 4 соединения прогреваются (`models.retrieve`), пока звучит приветствие.
- **Вход:** `sendAudio` → decode → `EchoMeter.line` → VAD → (кадры) расшифровщик. На паузе звук
  не идёт никуда (и не оплачивается), звучащий перевод и очередь сбрасываются.
- **Тикер** 50 мс → `floor.tick()`.
- **Приветствие:** текст по прежней цепочке (метаданные звонка → воркспейс → платформа), озвучка
  тем же голосом при старте; через `greeting_delay_seconds` (по умолчанию 5) встаёт в голову
  очереди ядра и звучит в первую тишину, но не позже 6 с. В транскрипт не пишется.
- **Транскрипт и Socket.IO:** по мере роста текста реплики — `call:transcript` `isFinal:false`
  с оригиналом (не чаще раза в 250 мс); когда перевод реплики доиграл, был перебит или (для
  текстовой) готов — один `call:translation` `{call_id, speaker, original, translated,
  detected_language, timestamp}` и `call:transcript` `isFinal:true`, байт в байт как
  `StealthTranslator.emitTurn`. `speaker` — `subscriber`, если язык реплики — «мой», иначе
  `other`. Реплика без перевода пишется с `translated: ''` и `untranslated: true`. «Угу» и
  согласие, поздняя короткая реплика (`stale`) и сказанное перед самым сбросом остаются в
  транскрипте с `translated: ''` и `skipped: <причина>`, но на страницу не отправляются — как
  журнал aidispatch хранит сказанное, хоть и не переведённое.
- **Статистика** `translator:stats` раз в 5 с; таймаут простоя 5 мин без прозвучавшего перевода —
  кладём трубку; страховочный таймер 4 ч.
- **Смена движка:** `detach()` отдаёт carryover `{sessionId, startTime, transcript}` и пишет
  метрики своего отрезка; конструктор принимает carryover.
- **Завершение:** сперва учёт, транскрипт и метрики, потом сокеты (как в `call.py`).

## 4. Настройки

`platform_settings.translator_consecutive` — объект:

| поле | по умолчанию | диапазон |
|---|---|---|
| `model` | `gpt-6-luna` | `gpt-6-luna` \| `gpt-6-sol` |
| `end_silence_ms` | 700 | 300–3000 |
| `hard_end_ms` | 2200 | 800–8000 |
| `semantic_threshold` | 0.8 | 0.5–0.99 |
| `barge_in_words` | 5 | 1–15 |

Читается в начале звонка (кэш настроек 60 с, сбрасывается при сохранении). Правится в
`/admin/settings`, карточка «Translator»; `PUT /api/admin/settings` проверяет диапазоны Zod-ом.
Отсутствующее или битое поле → значение по умолчанию.

## 5. Метрики звонка

Миграция `00055`: `ALTER TABLE translator_sessions ADD COLUMN metrics jsonb` (nullable).

Пишется при завершении (и при `detach`) — `summary()` из `call.py`:
`engine: 'consecutive'`, `languages`, `model`, `voice`, `settings`, `utterances`, `counts`
(причины выпуска и сброса, перебивания, слияния, перезапуски, заготовки…),
`latency_ms {p50,p90,n}` («конец речи → первый звук»), `release_ms`, `judge_ms`, `barge_ms`,
`played_s`, `echo {present, correlation, return_db}`, `engine_usage`, `events` (≤ 300),
`costs` по частям, `cost_usd`.

`GET /api/admin/sessions` отдаёт `metrics`; в `/admin/sessions` раскрытая строка показывает блок
«Consecutive translation» рядом с транскриптом: движок/модель/голос, задержка p50/p90,
причины выпуска, перебивания, эхо, стоимость по частям, хронология (свёрнута).

## 6. Биллинг

`finalizeSession` получает стоимость провайдеров (клиенту она уходит × markup):

| часть | как считается |
|---|---|
| `stt` | минуты отправленного в расшифровку звука × цена `openai-live-transcribe` ($0.017/мин) |
| `llm` | токены перевода по цене модели (`gpt-6-luna` $0.10/$0.50, `gpt-6-sol` $2/$10 за 1M) + токены судьи (`gpt-4.1-mini`) |
| `tts` | символы, отправленные в озвучку (включая выброшенные заготовки и приветствие), по цене `openai` за 1K символов |
| `telephony` | как сейчас |

Новые строки — в `PRICING_DEFAULTS` (`config/pricing.ts`), значит админские оверрайды цен
работают. Провайдеры: `openai`. Оценка: ~$0.03–0.035/мин + телефония $0.013 ≈ **$0.045/мин**
(каскад сейчас $0.0506, но его TTS не учитывается вовсе).

## 7. Проверка

### 7.1 Тесты

Раннер без новых зависимостей: `"test": "node --import tsx --test \"src/**/*.test.ts\""`;
`*.test.ts` исключены из сборки `tsc`. Переносятся тесты aidispatch: `policy`, `floor`
(сценарии из спек на подставных часах), `echo`, `playback`, `engine` (подставной клиент OpenAI),
`judge`; для `transcribe` и сборки звонка — ключевые сценарии на подставных частях. Плюс свои:
`audio` (µ-law туда-обратно, пересэмплинг), `twilio-out` (темп, `clear`), `vad` (на синтезе речи).

### 7.2 Сцена прогона

`src/scripts/consecutive-smoke.ts` — порт `consecutive_smoke.py`: та же сцена (незаконченная мысль
с паузой 0,9 с, «Yeah.» поверх перевода, диктовка номера, «Нет, подождите…» поверх перевода,
продолжение в первые секунды перевода, минутный монолог с паузами, «Stop.»), голоса A/B
озвучиваются `gpt-4o-mini-tts`, линия — подставной сокет Twilio в реальном времени, эхо громкой
связи — `--echo-db`. Выход: стерео WAV (линия/мы) и JSON (реплики, хронология, задержки,
стоимость). Запускается в прод-контейнере (`node dist/scripts/consecutive-smoke.js`), ключ OpenAI
берётся из `credential-resolver` внутри процесса и не выводится.

### 7.3 Первый шаг реализации — проверка API

На ключе caller: доступны ли `gpt-live-transcribe`, `gpt-6-luna`, `gpt-6-sol`, `gpt-4.1-mini`,
`gpt-4o-mini-tts`; принимает ли `gpt-live-transcribe` `audio/pcmu`. Если какой-то модели нет —
стоп и решение со Славой.

## 8. Зависимости и инфраструктура

- `onnxruntime-web@1.30.0` (точный пин) — +~145 МБ к `node_modules`, нативного кода нет,
  работает на `node:22-alpine`. Спайк на Mac: Silero v5 — 0,41 мс на окно 32 мс, разметка верная.
- `packages/backend/assets/silero_vad_v5.onnx` — 2 327 524 байта, sha256
  `2623a2953f6ff3d2c1e61740c6cdb7168133479b267dfef114a4a3cc5bdd788f`, модель snakers4/silero-vad
  (MIT), взята из `@ricky0123/vad-web@0.0.30`. Dockerfile копирует `assets/` в образ.
- `docker-compose.yml`: `VOICE_ENGINE` по умолчанию `consecutive`, `REALTIME_TRANSLATE_MODEL`
  убирается. В прод-`.env` `VOICE_ENGINE=pipeline` меняется на `consecutive` при деплое.
- Удаляются `services/realtime-translator.ts`, `services/conference-translator.ts`; ссылки на них
  в комментариях исправляются. Раздел «Translator Architecture» в `CLAUDE.md` переписывается.

## 9. Откат

`VOICE_ENGINE=pipeline` в `.env` + `docker compose up -d backend` — голос на каскаде, без
пересборки. Для одного воркспейса — `translator_defaults.voice_engine = 'pipeline'`.

## 10. Риски

- **Модели на ключе caller** — проверка первым шагом (§7.3).
- **Эхо громкой связи.** У aidispatch эха на линии не было (конференция), у нас оно есть почти
  наверняка. Механизм тот же: замер включает текстовый фильтр, пять слов поверх перевода
  проверяет судья. Сцена с `--echo-db` — обязательная часть проверки.
- **Шум на громкой связи.** Детектор, считающий шум речью, не даёт переводу зазвучать. Silero
  с порогом 0,7 — та же защита, что в aidispatch; пороги детектора — константы модуля.
- **Расшифровщик сдался посреди звонка** (три обрыва подряд) — звонок идёт без перевода, как в
  aidispatch; в лог — ошибка. Переключение на каскад в таком случае — вне рамок.

## 11. Вне рамок

- stealth, песочница-тренажёр, dialer — без изменений;
- перенос стоимости первого отрезка при смене движка посреди звонка (давний пробел carryover);
- запись разговора своим микшером — у caller запись делает Twilio.
